# 1.4.9: Split Long Screenshots with Overlap

Split a long screenshot into readable pieces with the smart splitting and adjustable overlap introduced in **Snow Shot 1.4.9**. On Windows and macOS, choose the source image, check cut lines, set overlap and export the pieces in order. This is useful when a chat preview makes the full image too small to read.

The [1.4.9 Release](https://github.com/mg-chao/snow-shot/releases/tag/v1.4.9_snow-shot) was published on **November 6, 2026 (UTC)**. It also adds TIFF input/output, moving and resizing collage images, a global scrolling-capture action and HTTP proxy settings. It fixes copying after editing a scrolling capture. See [Changelog](../changelog.mdx) for the other changes.

## Inspect the source before smart splitting

Smart splitting finds useful boundaries; it does not repair a bad scrolling stitch. Open the source and check missing or duplicated lines and the start/end range. Fix the source using [scrolling-capture troubleshooting](./scrolling-capture-fixes.mdx) before splitting it. More pieces make an uncorrected source harder to audit.

## Import the image and verify cut direction

1. Search the main window for **Split selected images**, select the result and click its action row. With no file selection available, an empty **Image split** window opens.
2. Click **Select image** or drag in one file. Each window processes one image.
3. Inspect the cut lines: **Vertical** (垂直) means vertical cut lines; **Horizontal** (水平) means horizontal cut lines. To divide a tall image into top and bottom pieces, choose **Horizontal**. For left/right pieces, choose **Vertical**.
4. Choose **Smart split**, set the target **Image count**, wait for the preview and check whether a line crosses text.

## Review the lines yourself

The suggested boundaries do not establish which sentence must stay together. Enlarge the preview, add lines on the ruler when needed, drag existing lines away from text, and select an unwanted line before pressing Delete. Use **Equal split** for a prescribed count or **Exact split** for dimensions. Inspect the preview again after changing modes.

![Teaching diagram showing cut lines added and moved on the ruler](/images/guides/en/img-split-2.svg)

## Retain context with overlap

**Overlap width** keeps an additional pixel region outside each cut line. Zero adds no overlap. A positive value gives the previous piece's end and the next piece's beginning some common content. This intentional export choice differs from a duplicated scrolling stitch.

![Diagram of the shared pixel region retained on both sides of a split boundary](/images/guides/en/img-split-overlap.svg)

*Teaching diagram. Some overlap helps continuity; too much adds unnecessary repetition.*

Start with a small value such as **48 pixels** and inspect the boundary. That may not cover a whole line in a large-font source. Adjust it for the actual image rather than treating the example as a universal optimum.

## Save all and compare the seams

Click **Save all** (全部保存) at the bottom right, choose a writable folder and wait for completion. Open the generated subfolder and check the number of files. In order, compare the end of one piece with the start of the next. Each should retain complete content, with a shared area matching your overlap choice.

![Boundary comparison of the actual two exported pieces with shared context](/images/blog/split-result-152.webp)

*Actual exported output, with labeled boundary crops. Both pieces retain the same stretch of context.*

For partial success, inspect both the error and existing files before retrying. One exported image is not proof that the batch completed. For paper documents, use **Stitch to PDF**, then check order, paper and margins in the new workflow. See [image-to-PDF](../guides/image-editing/pdf.mdx).

Keep important source images before updating. The copy fix and splitting feature are separate changes. If copying still fails, save a PNG to inspect completeness, then report the precise scrolling→editing→copy sequence. For splitting failures, provide version, source dimensions, direction, mode, target count, overlap, actual file count and a sanitized boundary sample.
