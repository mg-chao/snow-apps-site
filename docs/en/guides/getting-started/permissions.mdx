# macOS permissions and first use

macOS controls screen capture, system input, and microphone access separately. Decide which features you need, then follow Snow Shot's permission prompts into system settings. Windows does not use this macOS permissions panel.

![Screen recording, Accessibility, Input Monitoring, and microphone permissions mapped to their tasks](/images/guides/en/start-permissions.svg)

*Instructional illustration: check each permission separately. Allowing one does not automatically allow the others.*

## Check permissions from the app

1. Open **Settings → App permissions** in Snow Shot's main window and inspect status. You can also use the guidance shown the first time a capture or another action needs access.
2. Find a permission that is not authorized and click **Go to settings**. Check that the app in the privacy list is the Snow Shot copy you are running.
3. Allow access as the system requests. If it asks you to quit and reopen, finish other editing or recording first, then restart Snow Shot.
4. Recheck the app's permission page and perform the relevant action. The **Authorized** status and a successful result are separate checks; investigate further if either is missing.

## Drag the app and enable access

This guidance applies to Screen & System Audio Recording, Accessibility, and Input Monitoring. Follow the next section for microphone access.

The helper uses the running copy’s name; Mini appears as **Snow Shot Mini**. Check the copy you are using.

1. In **App permissions**, click **Go to settings** for the relevant permission. When System Settings opens, locate the permission helper beside it.
2. If the current Snow Shot is already in the permission list, turn on its system switch. Otherwise, hold the **Snow Shot application row** in the helper, drag it into the permission list in System Settings, and release. Check that the entry actually appears; dragging alone does not grant access.
3. Turn on access for the current copy in the system list. Reopen the app if the system requests it, then check for **Authorized** in Snow Shot. Perform a capture or the relevant action and confirm the expected result.

The application row appears only when it can be dragged. If it is absent and the helper asks you to open the installed application, launch the installed Snow Shot and retry. If the permission is restricted by an administrator, the administrator must handle that restriction; dragging the app cannot remove it.

## Request microphone access for the first time

1. Open **Settings → App permissions → Microphone** and click **Go to settings**. If microphone access has not been requested before, the helper shows **Request access**. Click it to make the request. The microphone flow does not use an application drag row.
2. **Requesting…** cannot be clicked again. Allow access in the macOS microphone prompt, then wait for the system result. The request ending does not itself mean access was allowed.
3. After the system grants access, the helper closes automatically. Recheck **Authorized** for Microphone in Snow Shot, then record an MP4 with the microphone enabled. Stop it and play the file to check that your voice is audible.

If microphone access was denied before, the helper directs you to enable it in System Settings instead of showing the first-request button again. If it says microphone access is unavailable, open the installed application as instructed and retry. Resolve any administrator restriction first.

## Continue after closing the helper

The helper's upper-right **× (Close guidance)** only hides the help. It does not revoke system permissions or cancel a microphone request that has already been sent. Switching to another app, minimizing System Settings, or closing it can also hide the helper. Its disappearance does not mean authorization is complete.

Recheck **App permissions** in Snow Shot. If it still shows **Go to settings**, open that system permission page again. Preparation is complete only when the **Authorized** status and the actual task result are both correct.

## When each permission is needed

| Permission | Related tasks | How to verify after allowing |
| --- | --- | --- |
| Screen & System Audio Recording | Screenshots, screen recording, live image capture | Use the capture shortcut, Control+1 for a fresh configuration, select an ordinary window, copy it, and check the image. |
| Accessibility | System controls interacting with other apps, selected-text operations | Run the required action and check that text or target control is available. |
| Input Monitoring | Some global keyboard/mouse actions and recorded input effects | Test your configured shortcut, mouse action, or recording effect. |
| Microphone | Recording your voice | Enable the microphone, record a short clip, and play it to check audio. |

Enabling a recording webcam may also trigger system camera permission. Microphone, webcam, and system audio are separate inputs. Having microphone access does not prove system audio was recorded. See [recording audio and webcam](../recording/audio-camera.mdx) for setup and sound checks.

## Capture remains black or an action still fails

**A permission change has not taken effect.** Check whether the system requires an app restart. Quit and reopen the copy you are using, then recheck status.

**Several Snow Shot entries appear in system settings.** Identify the actual launch path. Applications and the mounted DMG may each contain a separate copy. Allow the copy you are using and retry; do not rely on the displayed name alone.

**Only some content can be captured.** Compare with an ordinary window first. System- or application-protected content may remain uncapturable even when access is granted.

**A shortcut still does nothing.** Check your binding and key conflicts, then inspect registration under [shortcut settings](../settings/shortcuts.mdx). Fresh configurations use Control+1, not Command+1. Permissions do not explain every shortcut failure.

Before reporting an issue, note the macOS version, Snow Shot version, actual app path, and failed action. Use [log export](../settings/storage-backup.md) for diagnostics, and check for personal paths you need to remove before sharing.
